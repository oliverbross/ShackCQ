### Remediation delta and current truth

- Branch `fix/android-kx3-panadapter-rf-correctness` starts exactly at `fb86c523905bb4c1323bc878ab68380a333c90e7`; the older baseline identity below is retained as historical implementation evidence.
- Capture proof now uses typed active client and device formats. `TRUE_96K_STEREO` requires matching 96 kHz stereo client/device formats on the selected active USB input; a 96-client/48-device or channel/encoding conversion is rejected. 48 kHz is opened and accepted only as a separate direct proof.
- Route, format, I/Q, calibration and display states are independent. Stopping clears live proof. A physical route loss invalidates enabled path-bound profiles.
- Stable valid-bin masks exclude edge/transition/DC regions from floor and auto-range statistics. The renderer publishes objective occupancy, saturation, valid fraction, contrast, comb and in-band/out-of-band metrics and reduces exact non-overlapping source intervals.
- Automatic spectrum and waterfall scales are independent and off the Compose thread. Generic KX3 flatness is disabled by default and legacy settings migrate once. Correction never amplifies invalid regions.
- I/Q save now requires two opposite known-tone offsets, at least 35 dB corrected image rejection, at least 6 dB improvement and stable coefficients. The UI remains orientation-unverified without this evidence.
- A/B/C spur captures are implemented but deliberately require the operator to establish each safe physical topology before retaining a label.
- Physical result: direct Android-reported 96 kHz had only `49.7%` useful bins; direct 48 kHz had about `95.8%` useful bins and is the recommended present mode. Both had `0%` displayed saturation after remediation. Retained raw PCM contains the same approximately 1 kHz harmonic comb at both rates (48/96-sample periodicity respectively), proving that it precedes FFT and rendering. Its physical source remains unresolved; it stays visible and warned, not hidden.
- A Creative Sound Blaster Play! 3 comparison proved a direct 48 kHz two-channel Android route but returned bit-identical channels, so it is a mono ADC duplicated to stereo and correctly fails I/Q validation. Its different spur family and much weaker 1 kHz-period correlation show that the StarTech comb is path-dependent rather than generated by the shared ShackCQ FFT/rendering code; neither adapter passed the still-required safely terminated A/B/C test.
- A direct StarTech-to-tablet capture reduced channel RMS by about 14/19 dB and reduced 1 kHz-period correlation from `0.301` to `0.068`; the broad 1 kHz comb disappeared. The original hub/peripheral/power/grounding environment was therefore a material contributor, but the hub alone is not yet isolated. The direct path still had `7.72 dB` channel imbalance, only `0.10 dB` median strong-pair mirror rejection, and no observed response to manual VFO movement, so it is not accepted I/Q. CAT-offline diagnostic operation now replaces the cached absolute frequency with `RF STALE`, labels the spectrum `RELATIVE OFFSETS ONLY`, and explicitly warns when mirror images dominate.

## Source truth and contradictions

- `core/portable/panadapter_dsp.*` is a fixed 1,024-point prototype with live-frame Gram-Schmidt, per-frame mean subtraction, incomplete normalization, a `-120 dB` floor, fixed smoothing, and centre-bin replacement.
- The C ABI exposes only the prototype through `shackcq_feature_context`; Android `NativeCore.kt` and `native_bridge.cpp` expose no panadapter calls.
- Android has no dedicated stereo-I/Q capture controller, Panadapter destination, spectrum/waterfall renderer, calibration, markers, replay, or route-proof UI.
- `AudioMonitorController` is a separate mono `MIC` + AGC + speaker monitor and is not a valid I/Q pipeline.
- `README.md`, `PRODUCT.md`, and `docs/PANADAPTER_DESIGN.md` overstate Android implementation relative to source. They must be reconciled to the completed source and evidence.
- No file under `ios/` will be edited, built, archived, installed, or tested in this task.

## Production data flow

```text
PanadapterScreen (coalesced immutable UI frame)
  -> PanadapterController (lifecycle, route, capture, replay, diagnostics, CAT actions)
  -> NativePanadapter / batched primitive-array JNI
  -> dedicated shackcq_panadapter_context
  -> shared PanadapterDsp (streaming complex DSP and coherent snapshot)

RadioState + existing send/direct CAT closures -> controller/UI frequency truth and explicit QSY
FeatureController spot/worked snapshots         -> optional overlay only
AudioManager/AudioRecord selected USB input     -> verified stereo PCM; never AudioTrack
```

The panadapter will not open a serial device, start a CAT poller, use the network from DSP/rendering, share the active DX feature handle, or feed I/Q into the audible monitor.
